News Sentiment Pipeline

How news_sentiment turns a ticker symbol into a BUY / HOLD / SELL call: where the news comes from, how each headline gets scored, and what changes when you ask it to compare two models instead of one.

01 — single-model runFetch → score → rate

A plain news-sentiment AAPL run is four hops. Each hop is a different module, and each module only knows about the one next to it — cli.py never touches FinBERT directly, and rating.py never touches the network.

The averaging rule

Each headline becomes +1 (positive), 0 (neutral), or -1 (negative). aggregate_rating averages those across every headline fetched for the ticker, then score_to_rating turns that average into a verdict: 

def score_to_rating(avg_score, buy_threshold=0.2, sell_threshold=-0.2):
    if avg_score > buy_threshold:
        return "BUY"
    if avg_score < sell_threshold:
        return "SELL"
    return "HOLD"

Ten headlines, four negative, three neutral, three positive averages to -0.1 — inside the ±0.2 band, so it reports HOLD, not SELL. The thresholds are constants in rating.py, not tuned against real returns — a deliberate first-pass simplification, not a finding.

02 — compare modeOne fetch, two scorers, two ratings kept apart

--compare changes exactly one thing: instead of one Scorer at the end of the pipe, there are two — FinBERT and a local Qwen2.5 LLM — and both score the same fetched headlines, so their ratings are directly comparable instead of each drawing from a different sample of news. 

def analyze_tickers_multi(tickers, news_source, scorers, count=20):
    results = {}
    for ticker in tickers:
        headlines = news_source.fetch(ticker, count)   # one fetch
        results[ticker] = {
            name: aggregate_rating(ticker, scorer.score_all(headlines))
            for name, scorer in scorers.items()          # N independent scores
        }
    return results
Why fetch once, not twice: if each model pulled its own batch of headlines, a disagreement between FinBERT and Qwen could just mean they read different news. Scoring the identical list isolates the variable you actually care about — the model, not the sample.

Two very different kinds of model, same interface

FinBERT is a classifier: give it text, it returns a label and a calibrated probability. Qwen is a text-generation model: give it a prompt, it replies in free-form sentences. Both are wrapped so the rest of the pipeline sees the same shape — score(headline) → ScoredHeadline. 

def parse_llm_sentiment_label(text):
    text_lower = text.lower()
    positions = {label: text_lower.find(label) for label in _LABEL_SCORES}
    found = {label: pos for label, pos in positions.items() if pos != -1}
    if not found:
        raise ValueError(f"Could not parse a sentiment label: {text!r}")
    return min(found, key=found.get)   # whichever label word appears first

Qwen's reply to "Respond with exactly one word: Positive, Negative, or Neutral" might come back as "Neutral." or "Sentiment: Positive, because..." — this function finds whichever of the three words appears earliest and uses that, raising rather than guessing if none appear. Because that confidence isn't a real calibrated probability the way FinBERT's is, Qwen's ScoredHeadline.confidence is fixed at 1.0.

03 — module mapOne job per file

Why this is easy to test without a network or a GPU

news_source.py and sentiment.py are the only two modules that touch the outside world, and both take their dependency as a constructor argument — a ticker_factory, a classifier, a generator. Every other module, including the whole compare-mode pipeline, is tested by handing it a fake that returns canned data instead of calling Yahoo Finance or loading a model. That's what keeps a 54-test suite running in under a tenth of a second.
